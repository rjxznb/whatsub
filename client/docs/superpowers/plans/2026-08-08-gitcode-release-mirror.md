# GitCode Release Mirror Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace JiHuLab with a verified GitCode release mirror for app updates and yt-dlp, while retaining GitHub as the canonical fallback.

**Architecture:** GitHub publishes first. A reusable GitCode mirror workflow copies versioned assets, rewrites the signed updater manifest to GitCode URLs, verifies anonymous Range downloads, and atomically updates `main/latest.json`. New clients use GitCode then GitHub; old clients are forced to the existing GitHub fallback by invalidating the stale JiHuLab manifest.

**Tech Stack:** GitHub Actions YAML, Bash/curl/jq/gh, Node.js ESM + `node:test`, Tauri 2 updater JSON, Rust/TypeScript configuration.

## Global Constraints

- GitHub remains the canonical release source and is published before GitCode.
- Never alter the minisign signatures generated by Tauri.
- Never delete historical GitHub releases.
- GitCode health checks use anonymous `GET` with `Range: bytes=0-0`; `HEAD` is forbidden because GitCode returns 401.
- GitCode PAT is stored only as GitHub secret `GITCODE_TOKEN` and scoped to `rjxznb/whatsub-release`.
- `dry_run=true` must not publish to GitHub or GitCode.
- Preserve both `windows-x86_64` and `darwin-aarch64` during single-platform releases.
- Do not stage or modify the user's unrelated `../.agents/skills/` or `../AGENTS.md` files.

**Interfaces:**
- Consumes: workflow input `tag`, secret `GITCODE_TOKEN`, public GitHub release `rjxznb/whatsub-releases`.

- [ ] **Step 2: Run the contract test and verify failure**

```powershell

```

- [ ] **Step 3: Implement the reusable workflow**

The workflow must:

1. Resolve an explicit tag for manual dispatch or the caller-provided tag.
2. Download GitHub `latest.json` and current Release assets with `gh release download`.
3. Parse every updater URL with `gitcode-manifest.mjs`; download older carried assets from their original GitHub tag when needed.
4. Ensure the corresponding GitCode tag and Release exist through `api.gitcode.com/api/v5`.
5. Obtain each Release attachment upload URL and upload via `curl --upload-file`/the API-prescribed multipart request without printing the token.
6. Treat an existing same-name asset idempotently by deleting/replacing it.
7. Verify every manifest URL using `curl -L --fail --range 0-0` and require HTTP 206 plus `Content-Range` total size greater than zero.
8. Clone `rjxznb/whatsub-release`, replace `latest.json` only after verification, commit as `whatsub-release-bot`, and push `main` using a temporary credential file removed by a final cleanup step.
9. Set concurrency group `gitcode-release-mirror` with `cancel-in-progress: false`.
