# Whisper 模型自动校验与修复设计

## 背景

Windows 用户解析本地视频时，`whisper-cli` 可能以 `-1073741819`
（`0xC0000005`）崩溃。现场日志停在模型初始化阶段，模型路径指向用户目录中的
`ggml-base.bin`。当前实现只通过 `Path::exists()` 判断用户模型是否可用，并始终让
用户模型覆盖安装包内置模型，因此截断、被代理替换或内容损坏的文件也会直接交给
原生 `whisper-cli`，最终被误报成“视频文件或音轨有问题”。

本设计让客户端自动识别并修复模型问题，不要求用户检查文件大小、计算哈希、改名或
手动重试。

## 目标

1. App 下载的 Whisper 模型在启用前必须通过完整性校验。
2. 已存在的旧模型首次使用时自动完成一次完整校验，后续启动不重复扫描数 GB 文件。
3. 损坏的 `base` 用户模型自动让位给安装包内置 `base`。
4. 损坏且没有同型号内置副本的模型自动重新下载，解析任务等待修复后继续。
5. 已验证模型仍触发 Windows 原生访问异常时，自动关闭 GPU 并用 CPU 重试一次。
6. UI 显示实际修复过程；最终失败时给出模型或 GPU 相关提示，不再归咎于视频文件。

## 非目标

- 不在每次识别前重新计算完整 SHA256。
- 不修改用户选择的 Whisper 型号。
- 不因模型异常自动切换到更小、识别质量不同的型号。
- 不无限重试模型下载、GPU 或 CPU 转录。

## 模型完整性元数据

在 Rust 模型清单中，为每个 App 支持的官方模型保存：

- 型号名；
- 下载 URL；
- 精确字节数；
- 官方 SHA256；
- 用于进度展示的近似 MB。

校验规则分为两层：

1. **快速校验**：文件存在、字节数完全一致、前四字节是 GGML magic。
2. **完整校验**：流式计算 SHA256，并与内置清单比对。

下载到 `.partial` 后必须完成两层校验，成功后才允许原子重命名为正式模型文件。

## 持久化验证凭据

每个通过完整校验的用户模型旁边保存一个小型验证凭据文件，记录：

- 清单中的 SHA256；
- 文件字节数；
- 文件修改时间。

使用模型时：

- 快速校验失败，立即视为损坏；
- 快速校验通过且验证凭据仍匹配文件大小、修改时间和当前清单 SHA256，不再重复哈希；
- 没有凭据或凭据过期时，执行一次完整校验并刷新凭据。

这样旧版本遗留模型会在首次使用时得到验证，而 `large-v3` 等大模型不会在每次解析时
重复读取数 GB 数据。

## 自动修复流程

`transcribe()` 在启动 `whisper-cli` 前调用统一的“解析并确保模型可用”流程：

1. 检查用户模型。
2. 用户模型有效：使用该文件。
3. 用户模型损坏且存在同型号内置模型：删除无效用户副本及验证凭据，使用内置模型。
4. 用户模型损坏且没有同型号内置模型：删除无效副本及验证凭据，自动重新下载该型号；
   下载并校验成功后继续当前解析任务。
5. 没有用户模型但存在内置模型：直接使用内置模型。
6. 用户从未下载过所选型号且没有内置副本：保持现有“模型未下载”行为，不因一次解析
   擅自开始大文件下载。自动下载只用于修复已经存在但校验失败的模型。

单次解析任务最多执行一次模型自动下载。自动下载失败后保留 `.partial` 供下次续传，
并返回明确的“模型自动修复失败”错误，不再进入循环。

修复期间通过现有流水线日志显示：

- `检测到 Whisper 模型异常，正在自动修复…`
- `模型修复完成，继续生成字幕`
- `GPU 初始化异常，已自动切换 CPU 重试`

## GPU 崩溃兜底

模型通过完整性校验后，如果 Windows `whisper-cli` 返回精确的
`-1073741819`（`0xC0000005`）：

1. 当前 GPU 尝试立即结束；
2. 清除 GPU 设备固定环境变量；
3. 参数追加 `-ng`，使用相同音频和已验证模型从头重试一次；
4. CPU 成功则任务正常完成，并记录已降级；
5. CPU 仍失败则返回原始 GPU 错误和 CPU 错误摘要。

其他退出码不触发 CPU 降级。CPU 降级最多一次，不与模型自动下载形成循环。

## 错误展示

本地视频排查弹窗在渲染通用文件清单前，优先识别以下错误：

- 模型校验或自动下载失败：显示模型修复说明和“前往模型设置”操作；
- GPU 访问异常且 CPU 也失败：显示显卡驱动/CPU 降级失败说明；
- 只有无法提取音频、无音轨或 ffmpeg 解码失败才显示现有本地视频排查清单。

自动修复成功时不弹错误窗口，只在解析进度日志中说明发生过修复或 CPU 降级。

## 并发与取消

- 模型自动下载复用单飞锁，同一型号同时只下载一次；其他解析任务等待同一个结果。
- 用户取消解析时，当前任务停止等待；当没有其他等待者时取消模型下载并保留
  `.partial`。
- 正式模型文件只通过“下载 `.partial` → 校验 → 原子重命名”产生，解析过程永远不会
  读取正在写入的模型。

## 测试

Rust 单元测试覆盖：

1. 精确大小和 magic 的快速校验；
2. SHA256 成功与失败；
3. 有效/过期验证凭据；
4. 损坏 `base` 选择内置副本；
5. 损坏非内置模型选择自动下载；
6. 下载校验失败不会产生正式模型文件；
7. Windows 访问异常只触发一次 CPU 降级；
8. `-ng` 参数和 GPU 环境变量清理；
9. 取消和并发单飞行为。

前端测试覆盖模型错误优先于通用本地视频排查清单，以及“前往模型设置”操作。

最终验证运行目标 Rust 测试、完整 `cargo test`、前端目标测试、完整 Vitest、TypeScript
类型检查和 `cargo build`。本次实现完成后先保持本地，不主动触发 CI。
