# Pro 托管 AI 配额耗尽恢复设计

## 背景

whatSub 托管 AI 的 Pro 配额按自然月计费。服务端在每次请求开始前检查额度；只要请求开始时尚未达到上限，就允许该请求完整结束并在流结束后记账，因此最后一次请求可以略微超过上限。下一次请求才返回 `quota_exceeded`。

客户端已经为视频分析提供每 50 条字幕一个持久化检查点，但目前把配额耗尽压缩成 `errorUpsell: boolean`：现有 Pro 用户会看到无意义的「升级 Pro」，不知道何时恢复，也不知道已经保存到哪里。开始新解析时也不会预检额度，可能先完成下载和 Whisper 才发现无法调用托管 AI。

## 目标

1. 托管模式开始新解析前轻量检查配额，已耗尽时不启动下载、Whisper 或 AI 请求。
2. 解析途中耗尽时明确显示已保存字幕位置和北京时间重置时间。
3. 已订阅 Pro 的用户不再看到「升级 Pro」，而是可以跳到设置中的模型厂商区域切换自己的 API。
4. 额度尚未恢复时不提供会立即再次失败的「继续解析」。
5. 保持现有检查点语义：已提交批次永久保留，未提交预览回退；恢复后不重新下载、不重新 Whisper。

## 非目标

- 不改变 Pro 月额度数值或服务端计费方式。
- 不做整段视频 Token 预估、额度预留或跨请求锁定。
- 不改变每 50 条字幕提交一次的持久化粒度。
- 不阻止使用自有 API 的用户开始解析。

## 设计

### 结构化配额错误

扩展客户端 `RelayErrorInfo` 和 `RelayError`，从服务端错误体保留：

- `code`
- `used`
- `limit`
- `periodResetAt`
- `upsell`

`quota_exceeded` 继续被归类为不可重试错误。错误文字仅用于展示，程序分支只依赖 `code` 和结构化字段。

分析 store 用一个可选的结构化错误详情代替单纯依赖 `errorUpsell`。通用错误仍按现有路径显示；只有 `quota_exceeded` 启用配额恢复界面。

### 开始前预检

仅当当前模型厂商是 `whatsub-managed` 时调用现有 `llmQuota()`：

- `used < limit`：照常开始。
- `used >= limit` 且 `tier === "pro"`：进入配额耗尽提示，不启动解析流水线。
- 查询失败：不阻塞解析，由真正的 LLM 请求继续作为服务端权威判断，避免临时网络问题误伤正常用户。
- 自有 API：完全跳过预检。

预检是用户点击开始时的体验优化，不替代每次 LLM 请求的服务端检查，因此并发窗口和最后一次请求略微超额仍是安全的。

### 解析途中耗尽

服务端在请求开始时仍有余额时让该请求完整结束：

- 若这一批 50 条全部解析并成功提交，新的检查点保留这一批。
- 若后续修复请求或下一批请求被拒，当前未提交预览清空，恢复到最后持久化检查点。
- 若发生在 summary 阶段，全部字幕保留，恢复后只重新请求 summary。

前台错误状态保存当前检查点的 `nextCueOffset` 和总 cue 数量，用于显示「已保存到第 N 条」。后台队列沿用自身已有的 `committedCueOffset` 和 `totalCues`，展示相同语义。

### 用户界面

配额耗尽文案示例：

> 本月 AI 额度已用完。已保存到第 150 条字幕，将于 2026/08/01 08:00 恢复；恢复后可从这里继续，无需重新下载或转录。

按钮规则：

- 显示「切换自己的 API」，跳转 `/settings` 并定位、强调模型厂商配置区域。
- 不显示「升级 Pro」。
- 重置时间尚未到时不显示「继续解析」。
- 本地时间已经越过 `periodResetAt` 后显示「继续解析」；真正请求仍由服务端最终校验。
- 其他分析错误继续显示原有「继续解析」。

设置页定位复用项目现有的 query/hash/高亮模式；若没有统一 helper，则增加一个最小的模型配置定位参数，不引入全局导航状态。

## 错误处理

- 服务端缺少 `used`、`limit` 或 `periodResetAt` 时仍按 `quota_exceeded` 展示，但省略无法确定的数字或时间。
- 预检网络失败时静默降级为正常启动。
- 恢复按钮点击后若服务端仍判定未重置，再次更新结构化错误，不丢失检查点。
- 非 Pro 的 `trial_used_up`、`free_used_up` 保持原有升级路径，本次不改变其商业提示。

## 测试

1. `parseRelayError` 正确保留 `used / limit / periodResetAt`，缺失字段时为 `null`。
2. `quota_exceeded` 不重试。
3. 配额提示格式化为本地时间并包含已提交 cue 数量。
4. Pro 配额耗尽不显示「升级 Pro」，显示「切换自己的 API」。
5. 重置前隐藏继续按钮，重置后显示。
6. 托管模式预检耗尽时不启动解析；预检失败时继续启动；自有 API 不查询配额。
7. 已有分析检查点测试继续证明失败时只回退未提交批次，summary 失败不重跑字幕。

## 验收标准

- Pro 用户在解析前或解析途中耗尽额度时，能够立即理解原因、恢复时间和已保存位置。
- 用户不会被引导重复点击必然失败的继续按钮，也不会被错误引导再次订阅 Pro。
- 切换自有 API 或月度重置后，可以从最后持久化检查点继续，无重复下载和 Whisper。
- 前端完整测试、类型检查以及服务端 LLM 路由相关测试通过。
