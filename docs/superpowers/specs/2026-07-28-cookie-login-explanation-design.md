# Cookie 失效登录解释设计

## 背景

前台导入 YouTube 视频时，`friendlyError()` 已能把 Cookie 过期、机器人验证和登录失效识别成明确的登录类错误，并生成标题、原因说明和登录动作。但 `ImportModal` 在收到这类错误后会隐藏错误对话框并立即调用 `site_login_start`。外部浏览器因此先于解释出现，用户无法知道为什么突然要求登录。

## 目标

1. 登录窗口只在用户明确点击后打开。
2. 打开前说明 Cookie 已失效或 YouTube 要求重新验证。
3. 复用现有错误分类、登录按钮和 Cookie 采集流程。
4. 登录成功后仍自动重试原来的导入任务一次。
5. 后台下载队列继续采用相同的“先解释、再登录”交互。

## 非目标

- 不改变 Cookie 的保存位置、CDP 浏览器启动方式或采集域名。
- 不把确定的 Cookie 错误纳入网络重试。
- 不自动替用户登录账号。
- 不触发发布或 CI。

## 交互设计

认证类错误出现时，前台保留现有“解析失败”诊断对话框，展示：

- 标题：“网站登录已失效”或“YouTube 要求登录验证”。
- 说明：“当前保存的 YouTube 登录信息已过期，重新登录后才能继续下载。”
- 主按钮：“重新登录 YouTube”。
- 次按钮：“关闭”。

只有主按钮调用现有 `beginSiteLogin()`。随后沿用“等待 YouTube 登录完成”界面。Cookie 保存成功后关闭诊断状态，并自动重试此前的 URL、画质和 Whisper 模型，不要求用户再次填写。

用户关闭诊断对话框时，不打开浏览器、不清除输入，也不自动重试。

## 错误流

1. Rust 返回 yt-dlp stderr。
2. `friendlyError(error, phase, sourceUrl)` 生成登录类诊断和 `SiteLoginAction`。
3. `ImportModal` 显示诊断，不在 effect 中启动登录。
4. 用户点击登录按钮后调用 `site_login_start`。
5. `site-login-success` 保存 Cookie 并重试原任务。
6. `site-login-cancelled` 回到诊断界面，保留错误原因和输入。

机器人验证与明确 Cookie 过期均走此流程。普通网络错误、视频删除、私有视频和格式错误不得打开登录流程。

## 测试策略

- 登录类错误先显示原因，首次渲染不调用 `site_login_start`。
- 点击“重新登录 YouTube”后才调用 `site_login_start`。
- 登录成功后原导入参数只重试一次。
- 用户关闭或取消登录时不重试。
- 普通网络错误不显示登录主按钮。

## 风险与降级

这会比当前行为多一次用户点击，但消除了无解释弹窗。所有后端登录能力保持不变；若诊断 UI 出现问题，错误仍可通过现有详情区查看，不影响原始错误返回。
