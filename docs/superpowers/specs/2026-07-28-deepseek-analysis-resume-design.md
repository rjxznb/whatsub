# DeepSeek 分批重试与断点续析设计

## 背景

DeepSeek 使用 OpenAI 兼容接口 `https://api.deepseek.com/v1/chat/completions`。当前每个请求只发送一次，没有超时重试、退避或可重试状态码分类。任一发送或流读取错误都会终止整次分析。

失败后的前台按钮调用 `retranscribe_video`，会重新运行 Whisper、删除 `analysis.json` 并从第一条字幕重新分析。现有恢复位置以 `subtitles.length` 推算，但模型可能跳过音乐、标点或空字幕，因此“输出条数”并不等于“已消费输入条数”，会造成重复或错位。

## 目标

1. 临时网络错误在当前 DeepSeek 批次内自动重试，默认初始请求后最多重试 3 次（共 4 次尝试）。
2. 已完成批次只提交一次，失败批次不泄漏半截输出。
3. 持久化准确的输入字幕游标，失败后从当前批次继续。
4. DeepSeek 失败绝不自动重新运行 Whisper 或删除已完成分析。
5. 前台与本地后台分析共用相同的断点语义；远端导入队列在后端补充 `videoId`、阶段和检查点字段后再接入同一语义。
6. 用户取消、鉴权失败和不可恢复响应立即停止，不做无意义重试。

## 非目标

- 不改变分析提示词、每批 50 条字幕的默认大小或模型选择。
- 不保证在应用被操作系统强制杀死时保留未成功完成的当前批次。
- 不把 400、401、403、许可证/额度错误或无效响应当成网络波动。
- 不重新转录，除非用户明确选择独立的“重新转录”。
- 不触发发布或 CI。

## 重试边界

重试单位是一个输入字幕批次，不是单个流片段，也不是整个视频。

每批执行流程：

1. 记录 `startCueOffset` 和 `endCueOffset`。
2. 将流式解析结果缓存在当前批次内存中，不立刻追加到全局结果。
3. 请求成功结束并完成解析后，一次性提交该批输出。
4. 提交后持久化 `nextCueOffset = endCueOffset`。
5. 若发送或读取失败，丢弃当前批缓存，并重试同一输入范围。

这样即使模型跳过若干输入条目，游标仍按输入范围推进，不依赖输出数量。

## 可重试错误

自动重试以下情况：

- `fetch` 发送失败、连接重置、DNS/TLS 临时错误。
- 流式响应读取中断。
- HTTP 408、429、500、502、503、504。

不重试以下情况：

- `AbortSignal` 取消。
- HTTP 400、401、403。
- 授权、许可证或额度明确不足。
- JSON/结构持续不符合协议。

初始请求失败后最多重试 3 次（共 4 次尝试），使用可取消退避，基准约为 500ms、1500ms、3500ms，并尊重合法的 `Retry-After`。第四次尝试仍失败才向用户显示错误。

## 持久化格式

在 `analysis.json` 中增加向后兼容的可选检查点：

```ts
type AnalysisCheckpoint = {
  version: 1;
  transcriptFingerprint: string;
  nextCueOffset: number;
  phase: "cues" | "summary" | "complete";
  revision: number;
};
```

旧文件没有检查点时继续加载现有字幕，按兼容逻辑建立一次新检查点；新文件恢复时必须校验 transcript 指纹。指纹不匹配则不复用游标，避免字幕变化后跳过内容。

保存通过串行写队列完成，并由 Rust 写入临时文件后原子替换 `analysis.json`。`revision` 防止较旧的异步保存覆盖较新的检查点。

## 用户恢复流程

- 自动重试期间保持“正在解析”，可在日志中显示“网络波动，正在重试 DeepSeek（2/3）”。
- 重试耗尽后提供“继续解析”，读取 transcript 和检查点，从 `nextCueOffset` 开始。
- “重新转录”改为独立的破坏性操作，并明确提示会重做字幕和分析。
- 若字幕批次已完成但摘要失败，保留全部字幕分析并只重试摘要。

本地后台任务需保存 `videoId`、当前阶段和检查点。有效 transcript 已存在时，分析阶段重试不得再次调用 `import_video`。

当前远端导入队列接口只返回 URL、状态和错误，没有 `videoId`、处理阶段或检查点；因此跨应用重启的队列续析不能由桌面端单独可靠实现。该能力需要许可证/队列后端先扩展契约，作为独立后续项目处理。本次桌面端修复仍保证一次运行中的 DeepSeek 波动不会重跑 Whisper，并保证播放器与本地后台任务可从持久化检查点继续。

## 测试策略

- 发送失败和流读取失败会重试当前批次，成功后只提交一次。
- 429 尊重 `Retry-After`；401、取消和许可证错误不重试。
- 第三次失败后检查点不前进。
- 模型漏掉输出条目时，检查点仍推进到批次输入末尾。
- 重新进入播放器后从 `nextCueOffset` 恢复，而不是 `subtitles.length`。
- 点击“继续解析”不调用 `retranscribe_video` 或 `delete_analysis`。
- 摘要失败只重试摘要。
- 原子保存与 revision 防止旧写入覆盖新进度。
- 旧版 `analysis.json` 仍可正常加载。

## 风险与降级

批次级事务意味着网络在批次末尾断开时，最多重做当前 50 条输入，但不会重复已提交批次。检查点字段保持可选，旧文件不需要迁移脚本。若原子替换失败，保留原文件并返回保存错误，不写出半截 JSON。
