# Import、登录与首次配置错误体验设计

## 背景

当前有三类用户体验问题：

1. yt-dlp 明确返回 `Unsupported URL` 时，whatSub 仍显示通用“排查清单”，把确定性的不支持错误混同为网络、Cookie 或格式故障。
2. 首次配置 DeepSeek 的教程把充值说明附在粘贴密钥步骤里，不够醒目。
3. 邮箱验证码登录在连接服务器失败时直接显示 reqwest 的英文底层错误，例如 `error sending request for url (...)`；同时验证码成功后会由服务端立即清除，因此不能对所有失败盲目重试。

## 目标

- 所有 yt-dlp `Unsupported URL` 错误统一显示“暂不支持该链接”。
- DeepSeek 教程将充值拆为独立编号步骤，文案为“充值 5 块钱就够用”。
- 邮箱登录仅对确定发生在建连阶段的失败自动重试两次，并向用户显示稳定、明确的中文提示。

## 非目标

- 不新增任何受支持网站或 Apple Music 解析能力。
- 不根据域名维护“不支持网站”清单；错误判断以 yt-dlp 的实际输出为准。
- 不对验证码错误、HTTP 响应、超时或响应中断自动重试。
- 不改变服务端验证码生命周期或认证接口。
- 不在本任务中继续此前暂停的 DeepSeek 分析 generation/lifecycle 持久化重构。

## 设计一：通用的不支持链接诊断

### 判断边界

错误分类层检测 yt-dlp 输出中的 `Unsupported URL`，匹配时不依赖具体域名。匹配应大小写不敏感，并允许错误前后包含 yt-dlp 的其他日志行。

### 用户界面

- 标题：`暂不支持该链接`
- 建议：`当前下载工具无法解析这个链接。请换一个受支持的视频链接，或先下载为本地音视频文件后再导入。`
- 保留完整原始错误详情，供复制和后续排查。
- `generic` 不得为 `true`。
- 不设置 `retryable`、`loginRequired` 或登录 action。

该分类必须位于网络、Cookie、格式和通用下载失败之前，保证确定性错误不会进入排查清单。

### 使用范围

所有调用 `friendlyError()` 的前台导入、后台下载队列和 AI 工具导入共享同一分类结果，不在各个组件重复判断 URL。

## 设计二：DeepSeek 五步配置教程

DeepSeek 首次配置帮助调整为五个独立编号步骤：

1. `用手机号注册并登录 DeepSeek 开放平台（国内直连，无需梯子）`
2. `左侧菜单点「API keys」→ 点「创建 API key」`
3. `名字填「whatsub」→「创建」，复制弹窗里出现的密钥（仅显示一次）`
4. `前往「充值」页面，充值 5 块钱就够用`
5. `回到 whatSub 粘贴密钥，然后点击「保存并验证」`

充值必须是独立编号步骤，不写“至少充值 5 元”，也不再用“余额为 0 才充值”的条件式表达。

其他模型供应商教程保持不变。

## 设计三：邮箱验证码登录的安全网络恢复

### 重试规则

邮箱验证码验证请求总共最多尝试三次：首次请求加两次自动重试。

- 第一次连接失败后等待 500ms。
- 第二次连接失败后等待 1500ms。
- 第三次连接失败后返回中文错误。

仅当 reqwest 明确报告连接建立失败（`is_connect()`）时允许自动重试。以下情况不得自动重试：

- 已收到任何 HTTP 响应，包括 4xx 与 5xx；
- 请求总超时；
- 已建立连接后的响应读取失败或连接中断；
- JSON 解析失败；
- 用户主动取消；
- 服务端返回 `wrong_code`、`no_code`、`too_many_attempts`、`rate_limited` 等业务原因。

原因是验证码匹配成功后服务端会清除验证码；若服务器已处理成功但响应丢失，自动重复提交可能得到 `no_code`，不能将这种不确定情况当作安全重试。

### 稳定错误分类

Rust 命令不得把 reqwest 的完整英文错误直接暴露给 UI。认证网络失败映射为稳定错误码，至少包含：

- `auth_connect_failed`：连接服务器失败，自动重试耗尽。
- `auth_result_uncertain`：超时、响应中断或响应读取失败，服务器是否已完成验证无法确定。
- `auth_protocol_error`：服务器响应无法解析。

服务端已返回的业务 `reason` 保持现有 `AuthResult` 处理方式，不转成网络错误。

### 中文用户提示

两个邮箱登录入口必须复用同一映射，避免 `AccountLoginDialog` 与 `LicenseGate` 文案漂移：

- `auth_connect_failed`：`无法连接登录服务器，请检查网络或代理后重试。`
- `auth_result_uncertain`：`登录结果未确认，请再次尝试；如果验证码已失效，请重新获取。`
- `auth_protocol_error`：`登录服务器返回异常，请稍后重试。`

失败后保留邮箱与验证码，退出“正在验证”状态，让用户可以主动再次点击登录。发送验证码请求也使用相同中文网络映射，但不因本设计自动重复发送邮件。

### 代码边界

- Rust 认证模块负责：错误来源识别、连接阶段有限重试、稳定错误码。
- 一个共享前端认证错误模块负责：错误码与中文提示映射。
- 两个登录组件负责：显示提示、恢复按钮状态、保留用户输入。

## 测试策略

### 不支持链接

- 任意域名的 `ERROR: Unsupported URL: ...` 返回“暂不支持该链接”。
- 结果不是 generic，不可重试，也没有登录 action。
- 同一错误在后台下载操作区不显示登录按钮。

### DeepSeek 教程

- 首次配置卡片按顺序显示五个步骤。
- 第四步精确包含“充值 5 块钱就够用”。
- 不再出现“至少 5 元”或“余额为 0”的旧文案。

### 邮箱登录

- 连接失败两次、第三次成功：共发出三次请求，延迟为 500ms、1500ms。
- 三次连接失败：返回 `auth_connect_failed`。
- HTTP 错误、超时、响应中断和协议错误只尝试一次。
- 两个登录入口对相同错误码显示相同中文文案。
- 失败后验证码仍在输入框中，按钮退出 loading 状态。
