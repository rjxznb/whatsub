# yt-dlp 已启动下载持续断点续传设计

## 背景

当前前台 yt-dlp 使用较短的网络参数和一次外层进程机会，适合快速暴露未开代理、Cookie 过期等下载前错误。阶段感知 watchdog 已能处理下载或合并卡死，并保留 `.part` 和分片，但普通的连接重置、TLS EOF 或 yt-dlp 分片重试耗尽仍会让已经下载一半的前台任务立即失败。

现有代码通过有效 `[progress]` 日志计数识别下载阶段，却没有把“本任务曾经开始传输”用于普通错误后的重试决策；每次新进程还会重置计数。

## 目标

1. 下载开始前继续快速失败，尽快提示代理、Cookie 或确定性错误。
2. 一旦任务产生真实下载进度，就持续使用 yt-dlp 断点续传，直到成功、用户取消或出现确定性错误。
3. 重试保留 `.part`、`.ytdl`、分片和已下载格式流。
4. 下载与合并阶段使用不同清理策略。
5. 重试等待可被用户取消，关闭进度窗口仍会杀死当前进程并停止后续重试。
6. 重试状态在日志和进度 UI 中可见。

## 非目标

- 不对视频删除、私有视频、Cookie 失效、机器人验证、格式不支持或缺少本地依赖进行无限重试。
- 不保留用户明确取消后的临时工作目录。
- 不改变后台任务当前更耐心的 yt-dlp 内部参数，除非统一策略需要复用状态分类。
- 不触发发布或 CI。

## 状态模型

在整个下载调用作用域维护粘性的 `everStarted`，而不是只看本次进程的计数。

以下任一事件将其永久设为真：

- 成功解析出一条有效 `[progress]`。
- 进入合并阶段，说明媒体流已经下载完成。

新一轮 yt-dlp 尚未输出进度时，`everStarted` 仍保持真，因此断线后的恢复进程不会被误判成“从未开始”。同时记录最后阶段 `Preparing | Downloading | Merging`，用于清理和提示。

## 错误分类与策略

先分类，再决定是否重试：

### 立即停止

- 用户取消。
- Cookie 过期、要求登录、机器人验证。
- 视频删除、私有、地区/年龄限制或格式不可用。
- yt-dlp、ffmpeg 等本地依赖缺失或无法启动。

这些错误即使发生在曾经开始下载之后也立即返回，由上层显示对应操作。

### 尚未开始

前台保留短 socket timeout、少量 yt-dlp 内部重试和一次外层尝试。网络不可达时尽快返回“检查代理/网络”，不进入持续循环。

### 已经开始

对连接重置、超时、TLS/DNS 临时错误、HTTP 临时错误、分片重试耗尽和 watchdog stall 持续重试，不设固定总次数。退避采用 3s、5s、10s、20s、30s，之后保持 30s 上限。每次等待都监听取消信号。

UI/日志显示“网络波动，正在断点续传（第 N 次，N 秒后重试）”，不弹失败对话框。用户可以通过现有叉按钮停止任务。

## 文件保留与清理

- 下载阶段错误：不清理下载目录，依赖 `--continue` 复用 `.part`、`.ytdl`、分片和已完成格式流。
- 合并阶段错误：删除不完整的 `source.temp.mp4` 和防御性的 `source.mp4`，保留音视频格式流，重新合并。
- 用户取消：沿用现有逻辑删除任务工作目录。
- 确定性终止错误：保留现有失败清理策略，不进入续传循环。

watchdog stall、普通网络错误和后台基础重试使用独立计数，不再共享一个会互相消耗的 `attempt`。

## 测试策略

- 前台下载在零进度网络失败后立即返回。
- Cookie 和视频删除错误永不重试。
- 产生一次进度后连接重置会进入续传。
- 后续进程零进度失败时，粘性 `everStarted` 仍保持真。
- 多次续传没有固定上限，退避封顶 30 秒。
- 取消可中断退避，并阻止启动下一进程。
- 下载阶段重试保留所有分片和临时文件。
- 合并阶段重试只删除合并输出，不删除格式流和 `.part`。
- watchdog stall 不消耗普通网络重试状态。
- 重试日志包含次数和等待秒数。

纯策略函数负责根据模式、`everStarted`、阶段、错误类别和取消状态返回下一步，使测试不依赖真实网络或启动 yt-dlp。

## 风险与降级

网络长期中断时任务会持续等待，这是“已开始就继续”的预期行为；用户始终可以取消。30 秒退避上限避免持续高频请求。确定性错误优先于 `everStarted`，防止过期 Cookie 或已删除视频陷入无限循环。
